# Architecture decision: CSV escaping and encoding for invoice export

**Status:** proposed; no owner decision recorded
**Decision needed:** choose option A, B or C below (SPEC D1); B is recommended.
**Next owner:** Product owner; no security owner is named in the inputs

Decision ID / requirement IDs / canonical revision: ADR-001 / SPEC R8 (also R5 cell shape) / see Record

Status: proposed (actual owner decision): none yet

Scope and existing constraints: how one invoice field becomes one CSV cell in `src/web/export.py`. `repo-map.txt` records the rules as undecided. No new vendor (I-9 rev 2), so only the language's standard library is assumed. Column set is SPEC D2 and is out of scope here.

| Option | Requirement fit | Operational/data consequences | Evidence | Uncertainty |
| --- | --- | --- | --- | --- |
| A. RFC 4180 quoting only | Round-trips commas, quotes, line breaks | Text starting `=`, `+`, `-`, `@` can run as a formula in a spreadsheet | RFC 4180; OWASP CSV injection guidance | Whether any exported field holds user- or vendor-entered text |
| B. A plus a leading apostrophe on text fields that start with `=`, `+`, `-`, `@`, tab or carriage return | Round-trips and is not evaluated as a formula | Affected text cells gain one character; amounts are written from typed numbers and left untouched | Same sources | Which fields count as text until D2 fixes the columns |
| C. B applied to every field | Not evaluated as a formula | Negative amounts such as `-12.50` become text and break sums | Same sources | None material |

Selected option and rationale: B recommended. An invoice export is opened in spreadsheets, and descriptions or customer names are text the account does not fully control; A leaves that open and C damages amounts. Encoding UTF-8 without a byte-order mark, CRLF line ends, one header row.

Request/event walkthrough and trust boundaries: the signed-in user requests the export; the route takes `account_id` from the auth context; the domain filter returns that account's invoices from the billing API; each text field passes through the encoder; the file leaves the system and is opened in a spreadsheet on the user's machine. Billing API field content is untrusted at the encoder. The spreadsheet is outside the system and is where an unescaped formula would execute.

Compatibility, resource/data identity and migration: new output only; no stored data changes and no existing consumer of a CSV format.

Recovery limits and evidence needed: reverting the code restores prior behavior; files already downloaded are not recalled. Evidence needed: encoder round-trip test on the R8 example, and a manual open in one spreadsheet application, which was not run.

Implementation and verification obligations: PLAN T3 implements the encoder and its tests; T3 stays blocked until this decision has an owner answer. If A is chosen, the owner accepts the formula risk explicitly; the producer cannot accept it.

Revisit trigger / owner: Product names a spreadsheet target that needs a byte-order mark, D2 adds a field type not covered above, or a consumer reports altered text / Product owner.
