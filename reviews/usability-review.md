## Findings

### U01 — First documented validation command fails

**Medium.** Paths: [README.md](../README.md), the adaptation section generated by [scripts/build.py](../scripts/build.py), and [scripts/validate_profiles.py](../scripts/validate_profiles.py).

Reproduction: run the first command shown in the README validation block or the guide's “Validate your profiles” block: `python3 scripts/validate_profiles.py`. The actual CLI requires both `--org` and `--project`, prints a usage error, and exits 2. This is an avoidable first-use failure before the user reaches the expected unresolved-readiness decisions. The full adaptation document already shows working explicit arguments.

Correction: use `python3 scripts/validate_profiles.py --org config/org.example.json --project config/project.example.json` in both entry points. Preserve the separate `--ready` example and explanation that unresolved templates intentionally fail it. Rebuild the generated HTML and execute the exact documented command.

### U02 — Suggested retirement search incorrectly returns no sources

**Medium.** Paths: source-index generation in [scripts/build.py](../scripts/build.py), filtering in [assets/app.js](../assets/app.js), and `index.html#evidence`.

Reproduction: set the evidence search to `retirement`, which is explicitly suggested by its placeholder. Static evaluation of the actual 31 `data-search` strings gives zero matches. `retire` instead finds O08 and O13. The retirement lifecycle is mapped to O08, so a reader following the interface's own instruction is given a misleading empty result.

Correction: index meaningful stage names and aliases, including retirement, alongside source claims. Including visible limitation text also makes searches such as member-only or paywall useful for evidence assessment. Verify the three suggested queries, a genuine no-match case, source-type filtering, and a source deep link after filtering.

### U03 — Mobile navigation removes the review destination

**Low.** Path: the `@media(max-width:800px)` rule in [assets/styles.css](../assets/styles.css).

Reproduction from CSS and DOM: `.sidebar nav a:last-child{display:none}` applies below 801 CSS pixels; the last link is “Security & usability review.” That destination remains available on desktop, but the mobile reader must scroll past the full evidence library to find it. There is no replacement shortcut.

Correction: retain the review link in the wrapping navigation. Verify its visibility, keyboard access and lack of page-wide overflow at narrow widths.

### U04 — Small stage numbers have insufficient contrast margin

**Low.** Path: `.stage-jumps span` and the corresponding hover background in [assets/styles.css](../assets/styles.css).

The 11px numbered labels use `#5879a5` on white. An sRGB relative-luminance calculation gives 4.475:1; on the `#eef3ff` hover background it is lower, approximately 4.03:1. These are secondary labels with an adjacent full stage name, so the task remains understandable, but their contrast should clear a 4.5:1 small-text target with margin.

Correction: darken the numbered-label color, for example to `#4d6d97`, and recalculate against both backgrounds. This numerical finding is not a full color/contrast assessment of the page or embedded diagrams.

## Effective behavior and content

- The page states its scope early and provides direct routes to lifecycle exploration and organization adaptation. Each stage has a concrete question, inputs, outputs, owner, completion gate and skill link. Native `details` elements keep the long page manageable without making its content depend on JavaScript.
- The organization/project/runtime distinction is consistent across the guide and shared contract. Null decisions are explicitly unresolved; empty permissions grant nothing. Structure validation, readiness declarations, runtime enforcement and actual authorization are distinguished. The validator's explicit example-profile command passed; the same command with `--ready` failed as expected with specific field paths.
- The shared contract permits reversible work using existing repository context when full profiles are absent. It avoids making a small task depend on completing the entire organization template. Skills describe inputs, evidence, limits and owner decisions; role briefs do not pretend to install or constrain agents themselves.
- All 15 skill entry points have names, descriptions and working shared-contract links. Reviewed relative Markdown links resolved. The page had no duplicate IDs or missing fragment targets. Its stage-to-source mapping and direct skill paths aid traceability.
- The static markup includes a skip link, a named navigation landmark, labeled search/select controls, a polite source-count status, native buttons/summaries, and focusable named table-scroll regions. CSS supplies explicit focus outlines and narrow-screen layout rules. These are implementation observations, not claims that keyboard or assistive-technology journeys passed.
- Diagrams initially use PNGs, each with alt text, a caption, and separate full-size PNG/GIF links. JavaScript enables an explicit play/pause control; pausing restores PNGs, and a reduced-motion preference change pauses playback. No-JavaScript markup hides enhancement controls while keeping the content and links present. The effect of these controls in a real browser is reserved for the integration check.
- Source type, review date, access status, source limitations and synthesis boundaries are clear. The DORA landing-page-only evidence and the member-only Medium article are disclosed. Mutable GitHub branches, absent commit snapshots, framework self-reports and the weak retirement sample are explicitly limited rather than presented as comprehensive proof.
