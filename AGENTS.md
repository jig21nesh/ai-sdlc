# Project rules: AI-SDLC skill pack

This repository is a skill bundle packaged for Codex (`plugin.json`) and Claude Code (`.claude-plugin/plugin.json`). It ships Markdown procedures, templates and research. It ships no runtime service, hook, agent definition or MCP server; skills instruct the host to use its own sub-agents.

## Layout

- `skills/<id>/SKILL.md`: one procedure per skill; `skills/<id>/assets/`: its output template.
- `skills/shared-contract.md`: rules every skill applies. Change shared behavior here, not in twenty places.
- `skills/manifest.json`: must list every skill directory, its templates, evidence IDs and profile fields.
- `config/`, `templates/`, `references/`: profiles, task brief and role briefs.
- `research/`, `data/`: source evidence. `index.html`, `research/evidence.json` and `data/evidence-map.json` are generated by `scripts/build.py`; edit the script, never the generated files.
- `reviews/`, `tests/skill_behavior/`: recorded validation runs and regression cases.
- `docs/adr/`: architecture decision records.

## Checks to run before any commit

```sh
python3 scripts/build.py
python3 scripts/check_skills.py
python3 scripts/check_site.py
python3 scripts/validate_profiles.py --org config/org.example.json --project config/project.example.json
python3 -m unittest discover -s tests -v
uv run --no-project --with coverage==7.6.10 sh -c 'coverage run --branch --include="skills/*/scripts/*" -m unittest discover -s tests && coverage report --fail-under=80'
node --check assets/app.js
node tests/test_controls.cjs
claude plugin validate .claude-plugin/plugin.json --strict
claude plugin validate .claude-plugin/marketplace.json --strict
```

## Conventions

- Python uses the standard library only. Propose any dependency before adding it. `coverage` runs through `uv run` and is not a package dependency.
- A script shipped inside a skill needs tests in `tests/` with at least 80% line and branch coverage.
- Adding, renaming or removing a skill means updating `skills/manifest.json`, the README tables and skill counts, and both plugin descriptions in the same change.
- Keep `name`, `version`, `description`, `author`, `repository` and `license` identical in `plugin.json` and `.claude-plugin/plugin.json`. Increment both versions for any change users will install.
- Do not put Markdown under `agents/`; Claude Code would load it as an agent.
- Do not add `CLAUDE.md` at the repository root; strict plugin validation rejects it. Claude Code reads `.claude/CLAUDE.md`, which imports this file.
- Skills, their templates and the shared contract name no host and use no host-specific invocation syntax; write "the host" and "sub-agent". Host-specific material belongs in the README install sections and in example files named for the host, and each such example needs a counterpart for the other host.
- A skill states a claim only with a source in `research/` or a link. Mark toolkit additions as additions.
- Skills write product artifacts to the user's project, never to this repository or a plugin cache.
- Skill outputs follow the output rules in `skills/shared-contract.md`. A change that makes outputs longer needs evidence that reviewers benefit.

## Workflow

- Branch, change, pull request. No direct commits to `main`.
- Record a decision that adds a pattern, integration or significant trade-off as a numbered ADR in `docs/adr/` in the same pull request.
- Changing a skill's behavior requires rerunning the affected cases in `tests/skill_behavior/cases.json` or stating that they were not rerun.
